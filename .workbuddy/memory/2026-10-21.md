## Cloudflare 后台两张 GEO 卡片的判定（03:35）

用户在 CF 后台看到两个提示，问我是否和我提的问题一致。**结论：两个都不是同一件事。**

### #1 Content Signals（"robots.txt 里没有 Content Signals"）
- 这是**内容使用偏好声明**（`ai-train` / `search` / `ai-input`），管的是"AI 拿到内容后能不能训练/用于搜索/作为输入"。
- 和我说的 **P0-3（403 拦截）不是一回事**：403 是网关层直接拒绝 bot 进门，Content Signals 管的是进门之后怎么用。**先得让它进得来，声明才有意义。**
- 对本站方向正确（三个信号都该是 yes：就是希望被引用和检索到），值得开。
- ⚠️ **但 CF 给的实施路径有坑**：它要求开启 **"Cloudflare managed robots.txt"**，让 CF 接管并维护 robots.txt。仓库里现在那份是手工写的，**含 20+ 条 AI 爬虫 Allow 规则，是 GEO 策略的核心资产**。一旦被 CF 生成的版本覆盖，这些规则可能丢失。
- 给用户的操作口径：先备份 `robots.txt`，开启后立刻 `curl https://yigelurenjia.com/robots.txt` 核对 Allow 规则是否还在，没了就改回自己维护。

### #2 Markdown for Agents — **对本站无效，别开**
- 看起来最对症（"直接给 AI 干净 markdown"），但 CF 官方博客原文写得很清楚：
  > "Cloudflare will detect this, **fetch the original HTML version from the origin**, and convert it to markdown before serving it to the client."
- **它不执行 JavaScript**。本站源站 HTML 只有 41 字骨架，转换完还是 41 字空壳。治不了 P0-1。
- CF 自己也在同一篇里承认了这个边界，并给出另一条路：
  > "**Browser Rendering /markdown REST API** supports markdown conversion **if you need to render a dynamic page or application in a real browser before converting it**."
- 而且这个功能是 **Pro 及以上**才给开（Beta 免费，但门槛在套餐）。

### 顺带查到的高价值事实：原始 md 文件本来就公开可访问
实测：
- `https://yigelurenjia.com/guide/resources.md` → HTTP 200，`Content-Type: text/markdown; charset=utf-8`
- `https://yigelurenjia.com/README.md` → 同上

## P0-1 方案对比（03:47）

用户要求对比「预渲染 vs 迁 VitePress」。扫描内容后给出的核心论证：

**推荐迁移 VitePress**，关键理由是——**预渲染会毁掉 Docsify 唯一的杀手锏**。

Docsify 相对其他方案的核心优势就是**零构建**：改 md → 推 git → 生效。
预渲染必须：改 md → 跑 headless 浏览器 → 生成 36 个 HTML → 推 git → 生效。
**一旦引入构建步骤，Docsify 的最大优势就没了**，而站点内容还在持续更新，每次都要重跑整套预渲染。
VitePress 同样是「改 md → 推 git → 生效」（CI build），体感一样，但拿到原生 SSG + 内置搜索 + 内置上一页/下一页。

**迁移成本实测数据**：
- 36 篇 md 内容基本可直接复用（标准 Markdown）
- Docsify 专有写法仅 **4 处**：`guide/resources.md` 里的 `?id=怎么买` 锚点链接，VitePress 需改成 `#slug` 格式
- 内链 111 条：路径不变，无需改动
- 图片 22 个：`/assets/img/` 路径不变，搬到 `public/assets/img/`
- `_sidebar.md`（56 行）→ 转 VitePress 侧栏配置
- `_coverpage.md`（28 行）→ 转 `layout: home` 的 hero 区块
- **最大工作量**：index.html 里 4 个自定义插件需重写（图片放大 / 百度埋点 / footer 注入 / canonical+title 更新）
- 粗略量级：约 2 天

**风险**：36 个 URL 必须完全对齐否则已收录页 404；百度对 URL 变化敏感，迁移后需在百度站长平台提交改版；建议借迁移顺手把首页从"封面页"改成内容页（一并解决封面看不到价值的问题）。
