## 全站优化审计（03:00）

通读了项目，给出分优先级的优化清单。核心结论（按投入产出比排序）：

**P0-1 内容对爬虫不可见（结构性致命问题）**
- Docsify 是纯客户端渲染，`index.html` 里 `#app` 只有 `.lrj-boot` 骨架，正文靠运行时 XHR 拉 md 渲染。
- 后果：`robots.txt` 白名单了 20+ AI 爬虫（GPTBot/ClaudeBot/PerplexityBot/CCBot…）、写了 `llms.txt`、加了 `EducationalResource` + `FAQPage` 结构化数据，但这些爬虫**基本不执行 JS**，访问任何一页读到的都只是"正在加载内容"。整站 SEO/GEO 投入回报接近 0。
- 解法：① 加预渲染（推荐，保留 docsify 交互）② 迁移 VitePress/Astro（内容全是 md，迁移成本低）③ 双轨静态页（不推荐）。
- 附带：JSON-LD 全站只有一份静态的，SPA 换页不更新，41 页共享同一份描述。解决 JS 问题后需按页注入 Article/BreadcrumbList。

**P0-2 移动端 CTA 路径错（直接影响收入）**
- `guide/resources.md`「怎么买」区首卡是"扫码进店"二维码，但主要流量是小红书→手机打开，**手机无法扫自己的屏幕**（截图→切App→相册扫码，4 步）。
- 真正一步跳转的 xhslink「直接打开店铺」按钮被降级为"不方便扫码？"兜底位。
- 建议：媒体查询在手机端把"直接打开店铺"提为主 CTA，二维码折叠为"给电脑/朋友看"。

**P1 内容资产闲置**

## 砍 GA4 + P0-1 复验（03:16）

**① 已砍掉 GA4**（`index.html`）
- 删除 head 里的 `googletagmanager.com/gtag/js` 异步脚本与 `dataLayer`/`gtag` 定义块。
- 插件内两处 gtag 调用一并删除：转化埋点 `lrjTrack()`、SPA 路由切换时的 `page_view` 补发。
- `window.__lrjLastGaPath` 改名 `window.__lrjLastPath`（仍用于 SPA 换页去重），配套局部变量 `gaPath` 改名 `curPath`。
- 保留：百度统计 `_hmt`（国内主流量）+ Cloudflare Beacon（海外/服务端）。
- 校验：`grep gtag` 全仓无残留；node `new Function()` 逐块解析，5 段内联 JS + 2 段 JSON-LD 全部通过。

**② P0-1 复验：问题真实存在，已用线上原始数据坐实**

沙箱网络恢复后实测（不带 JS，直接读 HTTP 响应体）：

| 目标 | HTTP | HTML 体积 | 去掉 script/style 后可见正文字数 |
|---|---|---|---|
| `/` | 200 | 43,640 B | **41 字** |
| `/guide/start-here` | 200 | 43,640 B | **41 字** |

- 两个 URL 返回**完全同一份** HTML（说明 SPA 回退在服务端是生效的，这点没问题）。
- 41 个字就是 `#app` 里的 `.lrj-boot` 骨架（"一个路人甲 · 结构化面试"+"正在加载内容"）。
- 正文标志词「从零开始怎么学」「状态一：还没开始」「推荐路径」「游击战法」**全部 0 命中**。
- 结论：**41 个页面对任何不执行 JS 的客户端，呈现的都是 41 个字的空壳。**P0-1 成立，且比预想更彻底。

**⚠️ 修正上一轮的一个说法**：我原话说结构化数据"也被浪费了"，这是错的。两份 JSON-LD 写在静态 `<head>` 里，**爬虫不需要执行 JS 就能读到**，实测 `FAQPage` / `EducationalResource` 均在。真正不可见的只有文章正文。问题在于这 41 页共用同一份 JSON-LD，等于 41 页在结构化数据层面互相重复。

**③ 复验中发现的新的 P0-3：Cloudflare WAF 正在 403 掉一批 AI 爬虫**

用不同 UA 探测 `/guide/start-here`：

| 爬虫 | 结果 |
|---|---|
| Baiduspider / 360Spider / Sogou | 200 放行 |
| Googlebot / Bingbot / Google-Extended | 200 放行 |
| ChatGPT-User / OAI-SearchBot / PerplexityBot | 200 放行 |
| **GPTBot** | **403 拦截** |
| **ClaudeBot** | **403 拦截** |

- 403 响应体是 `Your request was blocked.`，响应头 `Server: cloudflare`，确认拦截来自 Cloudflare 而非源站。
- **这意味着 robots.txt 里那 20 多条 Allow 声明有一半是空头支票**——写了允许，网关层却直接拒了。
- 待用户去后台确认：Cloudflare → Bots → 「AI Scrapers and Crawlers」是否开启，或 WAF 自定义规则里是否有按 UA 的阻断规则。
- 注意 GPTBot 被拦、ChatGPT-User 放行这种"同门不同命"的组合，正是 CF 按名单分别管控的典型表现。

**下一步待用户决策**：P0-1 走预渲染还是迁移 VitePress/Astro；P0-3 需要用户去 CF 后台核对放行策略。另：`内容素材/` 501 篇与付费资料的版权边界仍需用户确认。
