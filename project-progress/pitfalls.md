## 坑1：glob工具默认截断结果

### 问题描述
使用 `glob` 工具搜索文件时，返回结果被截断（显示 "Results are truncated"），只显示前100个文件。

### 实际情况
- **预期**：内容素材文件夹有约100个文件
- **实际**：有 **501个** markdown文件

### 影响
- 严重低估素材数量
- 制定计划时数据严重失真
- 原本以为"60个待整合"，实际是"460+个待整合"

### 根因
glob工具有安全限制：60s超时 + 100文件限制。

### 解决方案
使用bash命令替代：
```bash
# 统计文件数量
find "D:\Coding\lurenjia_mianshi\内容素材" -type f -name "*.md" | wc -l

# 列出所有文件
ls "D:\Coding\lurenjia_mianshi\内容素材"
```

### 教训
- 不要完全依赖单一工具的数据
- 重要数据用多种方式交叉验证
- 对"Results are truncated"保持警惕

## 坑2：未提前验证数据准确性

### 问题描述
在用户问"素材文件中还有大量的未使用的素材，远不止60个"时，我未经核实就承认了"60个"这个数字。

### 根因
- 之前某次会话中可能提到了"60个"这个数字
- 我没有自己去验证，就直接采用了
- 用户比我自己更清楚实际情况

### 教训
- 任何数据都要自己验证一遍
- 用户质疑时，第一反应应该是去查证，而不是承认
- "让我查一下"比"是的，你说得对"更专业

## 坑3：制定计划前未充分盘点现状

### 问题描述
在制定"4个待办任务"计划时，我对素材数量的认知是错误的，导致：
- 任务1的工时估算严重偏低
- 策略制定不切实际

### 正确流程应该是
1. **先盘点** - 用bash命令统计真实数量
2. **再分类** - 抽样阅读素材，了解内容分布
3. **后规划** - 基于真实情况制定计划

### 教训
- 磨刀不误砍柴工
- 数据驱动决策，不要凭感觉

---

## 坑4：对工具输出过于信任

### 问题描述
看到glob返回100个文件，就以为真的只有100个。

### 根因
- 工具返回了100个"匹配"的文件
- 没有注意到"truncated"提示
- 忽略了工具的限制说明

### 教训
- 工具输出永远需要人工复核
- 看到"truncated"、"limited"等关键词要警惕
- 关键数据用不同工具交叉验证
